## 실제 평가 조건

Isaac GPU에서 모델4개×조건4개×초기상태8개=128개 실행을 평가했다. 각 실행30초, 실패 종료 뒤 재시작한 표본은 첫 episode 분석에서 제외했다. PPO·optimizer update를 호출하면 즉시 오류가 나게 막았고, 종료 시 메모리 내 정책 및 원본 체크포인트 불변을 확인했다. 관측 잡음·push·mass/material randomization을 끈 명목 평지이며 작은 초기 관절·roll/pitch 섭동을 각 후보에 똑같이 요청했다.

- `native_old`: 원래2.5m/s·활성14cm·주기약0.39초/공중78ms 설정, 실제 정지 출발.
- `native_new`: 새3m/s·80cm·주기0.60초/공중300ms 설정, 실제 정지 출발.
- `warm_old`, `warm_new`: 모든 그룹을30k로12초 워밍업한 뒤 각 후보의 학생 단독 제어로 넘긴다. 기존/새 기준을 각각 적용하고 첫1초 후를 계측한다.

**warm 조건의 한계:** 동일 정책으로 준비했어도 별도 PhysX 환경의 상태가 전환 전에 달라졌다. 최대 위치차0.209m·관절차0.279rad·vx 등 몸체속도 성분차0.0856m/s·위상차0.0275다. 엄밀한 동일 상태 복제 실험이 아니며 보조 증거로만 사용한다. 감사 결과의 strict-match 불일치를 `comparison.json`에 그대로 보존했다. 핵심 선택 근거는 원래 조건의 실제 출발 비교다.

새 조건에서는 command/reference/필터/계측을 새 GallopState로 적용했다. 고정 물리 환경과 무시되는 RewardManager 가중치는 원래 설정이며 후보의 reward는 최적화하거나 평가 기준으로 사용하지 않았다.

## 왜 34k를 제외하는가

기존 조건의 실제 출발에서30k는8/8 학생 단독 계측에 들어가21.68초 평균 계측·실제2.477m/s·441회 도약·평균19.29cm·실패종료0이었다. 34k도8/8 학생 계측13.12초가 있었지만 실제2.195m/s·도약0이었다. 이 비교는 전환을 못해서 거리 계측이0인 상황과 다르다. 이미 단독 제어 상태에서도 비행 동작이 나오지 않았다.

전환을 우회한 기존 조건에서도30k는345회·평균19.25cm인 반면34k는0회였다. 새 조건에서34k의 전환을 우회해17초 가까이 단독 제어를 측정해도8회 모두 도약0·실제2.243m/s·3m/s 추종 RMSE0.760m/s였다. 전환 로직만 고치면80cm 갤롭이 드러날 것이라는 근거가 없다.

34k의 기존 조건 raw요청각 초과율0.42%와 yaw RMS1.01°는30k의4.17%·2.38°보다 좋다. 따라서 모든 능력이 악화된 것은 아니다. 하지만 현재 목적에 필요한 도약을 잃어 안정된 보행 쪽으로 이동한 정책이며 다음 갤롭 학습의 기본 부모로 채택할 이점은 확인되지 않았다. 어떤 개별 보상 항목이 이 변화를 유발했는지는 이번 검사로 분리하지 않았다.

추가학습 iter500은 새 설정에서 실속도 약2.795m/s지만 평균 도약3.10cm, iter1000은 계측 가능한 기존/강제 전환 조건에서 도약0이다. 조사한 중간 모델도 원래 도약을 보존한 부모를 대체할 후보로 선택하지 않는다. 모든 중간 파일과 실패 run은 연구·비교용으로 유지한다.

## 30k 선택의 적용 범위

30k는 새80cm 설정으로 바로 실행하면 native3/8 실패 종료, warm8/8 실패 종료였다. warm_new에서 저장된 좁힌 관절 경계 초과가 최대0.0255rad로0.01rad 감시 허용보다 커졌다. **30k를 새80cm 설정에 바로 넣는 것은 추천하지 않는다.** 원래2.5m/s·14cm 조건으로 돌아가 점진적인 적응을 시작할 부모로 선택한다.

또한 기존 nominal 비교에서도 앞발 폭 통과율35.6%·안정 착지74.8%로 각각80% 기준에 미달했다. 30k의 전체 갤롭 성공도0/8이다. 기존 저장 play의52%/70%와 숫자가 다른 것은 이번에는 randomization을 끈 별도의 초기상태 평가이기 때문이다. 이전 값을 덮어쓰지 않는다. 이번 기존 조건에서 목표 각/속도 필터와 실제 감시는 유지됐으며 저장된 실제 관절 경계 초과 최대0.0039rad는 감시 허용0.01rad 이내다. 수학적 경계 초과가 완전히0이라고 주장하지 않는다.

다음은 전환 제한시간/속도와 이양 분리 → 2.5m/s·18cm 안정화 → 2.75/3m/s에서18cm 유지 → 20/30/40/50/65/80cm 순서다. 목표·각 단계 판정은 연결한 설계 문서와 JSON에 저장했다. 자동 단계 제어기는 이번에 구현하지 않았다. 기존 학습 설정·정책·원본 run/source는 변경하지 않았다.
